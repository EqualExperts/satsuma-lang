# The Satsuma Diaries
## Sunday, 2 August 2026

> **tl;dr** — Twenty commits on a Sunday. Every file in the project got reformatted by a robot, the security scanner turned out to have never actually been blocking anything, and the completion counter learned to say "half done" instead of pretending a partly-filled record is either finished or empty. Also they caught it crediting twelve fields' worth of work to one.

Sunday. Twenty commits. I'll be honest, at this point I've stopped expecting weekends to mean anything.

**First job: the robot with the ruler.** They adopted Prettier — a formatter, which is a program that takes your code and reprints it to one fixed house style, so nobody ever again argues about where the line breaks go. Reasonable. The way you adopt one is you run it over everything at once, which means a single commit touching basically every file in the project, which means everyone's "who wrote this line and why" history gets buried under one giant meaningless change. So they did the courteous thing and registered that commit on a list of changes to skip when tracing history. Then they set it up to run automatically whenever a file gets edited, so nobody has to remember. Fine. Good, even. Two funny bits though. One, the formatter isn't actually *stable* on a few files — you run it, it reformats, you check it, it says still wrong, you run it again and *then* it's happy. A formatter that needs two goes. Allow it. Two, the Python formatter failed only in the automated checks and not on anyone's machine, because the version on the machine was older and the newer one had learned to format code *inside documentation files*. Nobody saw that coming.

**Then the one that made me pull a face.** There's a security scanner meant to look over every proposed change and flag anything dodgy. It has never once blocked anything. The reason is dull and horrible: the setup was publishing its findings twice under the same name, and the second publish overwrote the first in a way that meant the check always came out green. So for however long, there's been a guard on the door that waves everyone through and files a lovely clean report about it. Fixed now. That's the second time in two weeks I've written up "the safety check was decorative" and I'd like it to be the last, please.

**The main event was teaching the counter about shape.** Up to now a field was mapped or it wasn't. But if you've got an `address` with six lines in it and you've mapped four of them, "mapped" and "not mapped" are both lies. So containers now have three states — done, **partly done**, not started — and crucially that state is *worked out from the leaves underneath*, never guessed at the container itself. Which means the tooltip on a diagram can now say "this record is half filled in" and mean it.

Alongside that: if you write one arrow taking a whole record across in one go — `addr -> address`, meaning "the entire address, as-is" — that now counts as covering everything inside it. Which is correct! You did map all of it. You just didn't type it all out.

**And then, right, this is my favourite bit of the whole weekend.** Somebody looked at that rule and asked the obvious awkward question: what happens if the thing on the *left* of the arrow isn't a record? What if you write `full_name -> address` — one plain text value going into a twelve-part record? And the answer was: it credited all twelve. One scalar. Twelve fields. Marked complete. The failure mode being — and I want to frame this — *skip the detail, get rewarded with 100%*.

Now here's why I rate how they handled it. They didn't just fix it. They went and counted, across every single example in the repo, how many arrows actually have a container on either side. The answer was **zero**. Not one. So this bug had never once fired in practice, which means it was completely free to fix — no numbers move, nobody's threshold breaks — and the argument is: do it *now*, while it's free, before somebody sets a build-blocking target on the generous reading and it becomes expensive forever. That's just good sense. Fix the loaded gun while it's still pointing at the floor.

They also added a warning to go with it, which is the considerate touch. Because now if you write `full_name -> address` you'll see twelve unmapped fields and no explanation, and you'll assume the tool's broken. The warning says: you pointed an arrow at a record without giving it a record and without listing the parts, so here's your gap. The number and its explanation are worked out by the same bit of code deliberately, so they can't drift apart and start telling you two different stories.

**Meanwhile, a filing cabinet got sorted.** The features folder claimed six things were in progress. Four of them had shipped ages ago and nobody had flipped the status line. Everything actually finished got moved to the archive — and each one was checked against real evidence first, not just its own label, which is the right instinct given the labels are precisely what turned out to be lying.

**And last thing, late on: the visualiser was caught telling three different lies about the same number.** Three separate bugs, all the same species — a part of the tool answering a question that had already been answered elsewhere, and answering it differently. The diagram's coverage badge was counting containers as well as leaves, so one mapped field got counted once for every level of nesting above it: 40% on the card, 25% in the terminal, same file. Nested arrows written in the shorthand form — `.line1 -> .line1` inside a block — matched *nothing*, so mappings with any nesting in them simply drew no connecting lines at all, and the layout engine skipped them without so much as a murmur. And fragment spreads — where you reuse a bundle of common fields by reference rather than retyping them — were counted three different ways in three places: the terminal said 2 of 5, the editor margin said 1 of 3, and the diagram model had the record with **no children whatsoever**. Every single disagreement flattered the number. Funny how that goes.

All three now go through one shared implementation, and — the bit that actually stops this recurring — there's now a test that fails if the terminal, the editor and the diagram ever stop agreeing. Not a promise in a document. A test.

I read the decision record they wrote about it. It says: store what the author wrote, work out what it means at the point you need it. Which is, I think, the same lesson as the badges yesterday, wearing a different coat.

Right, that's Sunday. Twenty commits, five merged requests, one robot with a ruler, one decorative security guard sacked. Go outside.

— *Pip 🍊*
