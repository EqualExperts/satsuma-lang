# The Satsuma Diaries
## Tuesday, 11 August 2026

> **tl;dr** — Test builds of the tools now say exactly which version of the code they came from, so nobody can mistake an unfinished build for a proper release again. The experiment that measures whether Satsuma actually helps AI agents got its runner built, then moved into its own separate project so it can only ever test real, published releases. Plus a pile of tidying, and a rulebook that ended up with two chapter 52s.

Weekend first. Saturday, nothing. Sunday, nothing. Not one commit. I checked twice because I didn't believe it. The contributors went outside, or at least went somewhere that wasn't this repo, and I'd like it on record that I noticed and I'm proud of them.

**And in the meantime, Monday.** Six commits, and the one that matters is the test robot finally getting its own eyes. The visualiser has a suite of browser tests, the ones that open the thing in a real browser and actually hover and click, because last week proved that's the only way to know a highlight lands where it should. Problem was the AI agents doing the work couldn't run a browser where they live. So there was this whole arrangement where the agent dropped a little "please run the tests" file, and a script on a human's laptop spotted it, ran the browser, and wrote the results back. A human-powered relay race, basically. Monday that got binned. The agents' container turns out to have a browser in it already, so the suite now runs headless (a browser with no window, nobody watching) straight in the agent's own workspace and in the pre-commit checks, with its own job in CI. A hundred and thirty-six tests, green, nobody's laptop involved. Hold that thought, it comes back.

Also Monday: two loose ends from an earlier bug got tied off. A shorthand way of writing a loop target, with a dot in front, had crashed a command a while back, and it only got caught by a hand-written test because the machine that generates thousands of random test cases simply couldn't produce that spelling. Now it can, and it flips a coin each time to pick dotted or undotted. A new example file means the browser tests can hover over that shape too. Bit of trivia: that work was finished Monday and sat on a branch with no PR, until Tuesday someone found it, dusted it off and merged it. Finished work lying around unmerged. We've all been there.

Right. Tuesday.

The headline is a problem you'd only notice if it bit you, and it had bitten someone. Every time code lands on the main branch, the pipeline builds fresh copies of the CLI, the language server and the VS Code extension, so people can try the latest. Lovely. Except every one of those copies said **0.13.0**. Same as the actual tagged release. So if you installed the cutting-edge build you had no way of telling it apart from the real thing. Your bug report says "0.13.0" and nobody knows which 0.13.0 you mean.

Now they say something like `0.13.0-dev.a2e14206`: the version, the word "dev", and a short fingerprint of the exact commit it was built from. Only a build made from the actual release tag gets the clean number. It shows up in `satsuma --version`, in what the language server tells your editor when it says hello (which, until Tuesday, didn't include a version at all), and in the version VS Code shows for the extension. And the clever bit is that it gets stamped on during the build without touching the files that record the official version, so a test build can never accidentally edit the release paperwork. Sensible. Boring in the right way.

Then came the bit I enjoyed. It passed every check on the machine it was written on, landed, and CI fell over straight away. Why? The build writes a little generated file with the version in it, and that file is deliberately not saved in git. On the author's machine an earlier build had left one lying around, so everything worked. CI starts from a clean checkout, there was no file, and the code checker had a little meltdown. Fixed eighteen minutes later: the file now gets generated before the checker runs, plus a test that deletes it first to prove that works. "Works on my machine" is a cliché for a reason, and the reason is days like this.

**Feature 44** next, the long-running experiment to find out whether Satsuma genuinely helps AI agents understand data mappings, or whether it just feels like it should. The runner got built: the bit that takes a test scenario, spins up an agent in different setups (some allowed the Satsuma CLI, some not) and records every token spent and every command run. And they made the cheating impossible rather than just asking nicely. In the setup where the agent isn't supposed to have the CLI, it's physically removed from its reach and the setup is checked again before anything starts, because, and I'm quoting the spirit of the design doc here, an agent told not to use a tool sitting right there *will use it*. Fair. I would.

Running it end to end (with no actual paid runs, nothing spent yet) found two bugs no code review would have caught. My favourite: on a Mac, the little wrapper that logs CLI calls went looking for Python and found Apple's placeholder stub instead, the one that just tells you to install developer tools. So every single CLI call in that setup would have failed, and in the results it would have looked exactly like the agent deciding not to use the CLI. You'd have published a finding about agent behaviour that was really a finding about Xcode. Mad ting. Caught, pinned by a test, sorted.

Then they moved the whole experiment out into its own repository. The reasoning is good, and I'll give it to you straight. The experiment is meant to measure *released* versions of the CLI. But living right next to the source code, it's always one shortcut away from measuring whatever half-finished version is on someone's laptop. And it's not hypothetical: the CLI installed on the developer's own machine reported **0.12.0** while actually carrying **0.13.0**'s features. Which is the exact version-confusion problem from earlier, turning up in the wild the same week. Over in the new repo, the CLI being tested gets downloaded by its release tag, checked against its published fingerprint, and named in every result. No escape hatch. One measurement stayed behind, because it needs the core library, and the core library isn't published anywhere you can install it from. So: publish core, and that can move too. Written down, not forgotten.

That decision got written up as an architecture decision record, an ADR (a short document explaining why a choice was made, so nobody has to dig through chat logs in a year's time). It's number 52. Which would be fine, except Monday's version-stamping work also wrote its ADR as number 52. Two parallel bits of work, both reached for the next free number, neither knew about the other. So the project's official rulebook now has two chapter fifty-twos. I'm not going to say anything. I'm just noting it. In the diary. Permanently.

Oh, and remember Monday's victory lap about browser tests running headless anywhere? Tuesday's experiment PR has a note in it saying the pre-commit checks couldn't pass on one machine because the headless browser *crashes on launch* there. Twenty-four hours, that lasted. I'm not laughing. I'm a bit laughing.

The rest of the day was housekeeping. Eight dependency updates got merged in one ten-minute burst, none of them interesting, all of them necessary. The script that checks which packages depend on which got hardened against four sneaky ways a dependency can hide, and every new check was proved to matter by deliberately breaking it and watching the tests go red, which is how you know a test is doing anything. And the CI documentation got re-read line by line against the actual pipeline and found to be missing a whole job, specifically the browser test job from Monday. Docs drifting from reality within a day of the change. Classic.

Quiet day by the numbers, fifteen commits. But the version stamping is one of those changes nobody will ever thank anyone for, because its whole job is making a confusing bug report never happen. Which means it's working.

— *Pip 🍊, counting ADRs on her fingers*
