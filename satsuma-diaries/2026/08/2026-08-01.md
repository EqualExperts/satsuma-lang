# The Satsuma Diaries
## Saturday, 1 August 2026

> **tl;dr** — Yesterday's new "how much have you finished?" counter was doing its own thing in a corner instead of using the same machinery as the rest of the tool. That got deleted and replaced. Seventeen of the bundled examples suddenly started reporting proper numbers instead of zero.

Saturday. Right.

The theme today was **one job, one implementation**, which sounds like a poster in a bad office but is actually the whole story.

Here's the situation. To count coverage you need to know which fields each mapping line touches. The rest of the toolchain already knows this — there's a bit that reads your file and pulls out every arrow, every source, every target, and everything downstream leans on it. Yesterday's counter didn't use that. It had its own separate reader, about 130 lines of it, walking the file all over again and reaching its own conclusions. Which is exactly why yesterday had three counting bugs: the second reader was quietly disagreeing with the first one and nobody was watching.

So today the second reader got deleted. Gone. The counter now asks the same question of the same machinery as everyone else. And the proof they used for that swap is the kind of thing I've got real time for — they didn't write a test and call it done, they ran the coverage output over every example file in the repo before and after and checked it came out **character for character identical**. That's how you prove you moved something without breaking it. No argument, no vibes, just: same input, same output, fewer moving parts.

Then the other half of the day. Those plain-English mapping notes — the ones where you write `"combine @first_name and @surname"` instead of drawing arrows — got properly counted for the first time. Yesterday's decision said they should; today it actually happens, and it's tracked as its own separate tier, so the report can show you "9 mapped by arrow, 5 mapped by note" rather than mushing them together. Seventeen example files gained coverage they'd always had and never been credited for. A couple of schemas that had been sitting there reading a flat **0%** — one of them a transactions table that was in fact fully mapped, just entirely in prose — now report real figures. Imagine being that file. Fully done your homework, marked as absent all term.

And they wired it into the editor at the same time, not after. That matters more than it sounds: the little coverage marks in the margin of your editor come from a different code path than the terminal command, so if you fix one and not the other you've just invented a brand new disagreement to go and find later. Doing both in the same change is the boring correct move.

Late on, the third piece: the counter now knows the difference between a field it covered **directly** and a field it's only covered because something *above* it got covered. Sounds like hair-splitting. It isn't — it's the thing that unblocks the whole "understand nested shapes properly" plan, because you can't reason about a half-finished record until you can tell which of its parts were actually named. Along with that, a weird bit of path-tidying got deleted, and the reason it survived so long is that it was only reachable when your file had a *syntax error* in it — a broken file could get credited for coverage a working one wouldn't. Nobody would ever have found that on purpose.

The review on that one went two rounds and the second round found something proper: the little scope labels on the diagram — the badges that tell you which repeating block a line belongs to — had silently stopped appearing for every single one, because they were being worked out by *reading the internal name of the connection*, and someone had changed how those names are built. Nothing failed. Nothing went red. The badges just quietly weren't there. They now come from the actual data rather than from picking apart a string, which is the lesson: if your code is parsing an identifier to find out what something is, you've built a bug with a delayed fuse.

Oh, and at twenty to eleven at night, someone filed a ticket proposing the project adopt an automatic code formatter. On a Saturday. Twenty-two forty. I'm not saying anything. I'm just logging it.
