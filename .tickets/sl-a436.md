# viz-harness: give each Playwright run its own server ports

Two harness runs on one machine (two worktrees, or two agents committing at once) failed with "http://127.0.0.1:3333 is already used": the fixture and playground servers hardcoded 3333 and 3334. A pre-commit run failed this way on 2026-10-06 while another session's suite was running.

## Acceptance Criteria

- Each Playwright run picks free ports for both servers; two full suites can run concurrently.
- `SATSUMA_HARNESS_PORT` / `SATSUMA_PLAYGROUND_PORT` pin the ports; invalid values fail loudly.
- `npm run dev` still serves on 3333 by default.

## Notes

**2026-10-06T13:32:28Z**

Cause: Both servers and the Playwright config hardcoded 3333/3334, so concurrent runs always collided.
Fix: A shared scripts/harness-ports.cjs reads each port from an environment variable, falling back to 3333/3334. When the variables are unset, the Playwright config picks two free ports and exports them, so its workers and both servers agree. Proven by two concurrent full runs, 146/146 each.
