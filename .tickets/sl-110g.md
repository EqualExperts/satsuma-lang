# vscode: Release fails since 2026-09-29 — @types/vscode ahead of engines.vscode

Dependabot #553 bumped `@types/vscode` to ~1.134.0 while `engines.vscode` stayed at ^1.125.0. `vsce package` refuses to package an extension whose API types are newer than its declared minimum VS Code, so every Release run on main failed. CI stayed green because it never runs `vsce package`.

Decision (user, 2026-10-06): raise the minimum VS Code to 1.134 rather than pin the types back.

## Acceptance Criteria

- `engines.vscode` is ^1.134.0 in the manifest and the root lockfile.
- `npm run package` in tooling/vscode-satsuma builds the .vsix.
- A unit test fails when `@types/vscode` is newer than `engines.vscode`, so the mismatch fails CI in the bumping PR.
- CHANGELOG Unreleased entry for the raised minimum.

## Notes

**2026-10-06T12:00:00Z**

Cause: #553 raised `@types/vscode` past `engines.vscode`, which vsce rejects; only the Release workflow packages the extension, so CI never saw it.
Fix: raised `engines.vscode` to ^1.134.0 and added test/engines-types.test.js, checked to fail against the old value; `npm run package` builds the .vsix locally. (commit immediately after 9ad22188)
