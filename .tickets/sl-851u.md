# ci: wire test:typecheck into CI for core, LSP, and viz-backend

R2 (PR #445, tickets tcc-e35f/ef1b/yb3z/chls) added a compile-time CST-symbol regression (tsconfig.type-tests.json + npm run test:typecheck) to satsuma-core, satsuma-lsp, and satsuma-viz-backend, wired only into each package's npm run pretest. npm only auto-fires the pretest hook before a script literally named 'test', so it protects satsuma-cli in CI (whose CI job explicitly runs 'npm run pretest') but is silently skipped in CI for the other three packages: the 'tooling-modules' matrix job runs 'npm run test:coverage' directly for core/viz-backend, and the 'vscode-extension' job runs a bare 'npx tsc' + node --test for LSP. Neither path triggers pretest, so a stale/renamed grammar symbol in those three packages would currently pass GitHub Actions CI even though it fails locally via the pre-commit hook (which calls plain 'npm test').

## Design

Add an explicit 'npm run test:typecheck' (or 'npm run pretest') step to the 'tooling-modules' matrix job in .github/workflows/ci.yml for the satsuma-core and satsuma-viz-backend shards, and to the 'vscode-extension' job's LSP steps for satsuma-lsp. Keep satsuma-viz and satsuma-viz-model shards as-is unless they also define a type-tests project. No script or source changes needed — this is CI wiring only.

## Acceptance Criteria

A deliberately reintroduced stale grammar symbol (e.g. reverting one @ts-expect-error type-tests file to reference a removed symbol as valid) fails the relevant GitHub Actions job for satsuma-core, satsuma-lsp, and satsuma-viz-backend; existing CI jobs continue to pass on current main; no change to local pre-commit behavior, which already covers this via plain 'npm test'.
