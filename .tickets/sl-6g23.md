# viz: expand/collapse click target on a compact card is too small (arrow-only)

`_onToggleClick` (sz-schema-card.ts:1137) is deliberately isolated from `_onHeaderClick`/navigate — sl-tw0r fixed a bug where a combined handler caused expanding a card in a host that navigates on click (e.g. VS Code) to also yank the editor to the source file. Today only the small arrow glyph (`.header-toggle`, ~12px glyph + padding) is wired to toggle, which is a poor Fitts's-law target on a compact overview card.

Per user feedback: extend the toggle's click target to also cover the field-count text next to the arrow (`.header-count`, e.g. "28/30") while leaving the name/icon portion of the header wired to navigate only, exactly as sl-tw0r requires. Do not merge the toggle and navigate handlers.

Screenshot: bug-reports/only-click-in-arrow-expands-contracts.png

## Acceptance Criteria

Clicking the arrow OR the field-count text toggles expand/collapse. Clicking the name/icon still navigates and does not toggle. The existing sl-tw0r regression test (combined-handler navigate-on-expand) still passes.
